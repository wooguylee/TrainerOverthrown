# VVooOverthrown 한글 패치 및 오프라인 트레이너 설계

## 1. 목표

현재 `W:\Games\Overthrown` Windows 빌드에서 동작하는 하나의 실행 파일을 만든다.
이 앱은 한글화와 IL2CPP Helper의 설치·제거, 게임 빌드 검증, 게임 연결, 안전한
싱글플레이 트레이너 기능을 통합한다. 핵심 UI 한글화가 실제 게임 화면에 적용되고,
검증된 트레이너 기능 하나 이상이 실제 런타임에서 조회·변경되는 것을 첫 완성 기준으로
삼는다. 전체 번역과 추가 기능은 같은 데이터·기능 인터페이스를 통해 단계적으로 늘린다.

## 2. 범위와 안전 경계

### 포함

- 한국어 WPF 관리 앱
- 게임 경로 자동/수동 탐색
- 세 파일 SHA-256 기반 지원 빌드 판정
- 게임 폴더 변경 전 사용자 데이터 백업
- BepInEx IL2CPP와 전용 Helper의 manifest 기반 설치·제거
- 영어 원문 추출, 한국어 번역표, 용어집, 토큰·중복 검증
- TextMeshPro 기반 런타임 한글화와 한국어 글꼴 fallback
- 현재 연결 상태와 capability를 보여 주는 명명 파이프 통신
- 싱글플레이에서만 동작하는 검증된 플레이어 기능
- 전체 런타임 효과 초기화와 Helper 종료 시 복원
- 자동 테스트, 빌드, 패키지 체크섬, 간단 실게임 부팅 검증

### 제외

- 온라인·협동·경쟁 플레이에서의 변경
- 안티치트, DRM, Steam 또는 PlayFab 인증 우회
- 도전과제 강제 해제
- 임의 메모리 주소 입력이나 범용 메모리 편집기
- 원본 EXE/DLL 교체
- 세이브 복원 중인 게임 프로세스 강제 종료
- 검증되지 않은 기능을 성공한 것처럼 노출

## 3. 선택한 접근

전용 WPF 앱과 BepInEx 6 IL2CPP Helper를 사용한다. WPF 앱은 파일·프로세스·백업과
사용자 인터페이스를 담당하고, Helper는 Unity 메인 스레드에서 게임 상태와 UI를
다룬다. 두 프로세스는 현재 Windows 사용자만 접근 가능한 명명 파이프로 통신한다.

직접 Addressables 번들을 수정하지 않는다. 한글화 Helper가 번역 사전을 읽고
TextMeshPro 텍스트 setter 후킹과 보수적인 활성 텍스트 재검사를 조합해 표시 문자열을
교체한다. 번역표에 없는 문자열은 영어 원문을 그대로 보존하고 누락 키만 로컬 로그에
남긴다. 인터넷 번역은 런타임에서 사용하지 않는다.

## 4. 구성 요소

### `VVooOverthrown.App`

- .NET Windows WPF 단일 실행 파일
- 설치 상태, 빌드 지원 여부, 게임 실행 상태, Helper 연결 상태 표시
- 한글 패치/Helper 설치와 제거
- 게임 실행과 연결
- capability 기반 기능 화면
- 백업, 진단 ZIP, 로그 열기
- 멀티플레이 차단 사유와 복구 방법을 한국어로 표시

### `VVooOverthrown.Core`

- 게임 탐색 및 경로 검증
- 빌드 지문 계산과 allowlist 비교
- 안전한 임시 디렉터리, 원자적 복사, install manifest
- 사용자 데이터 백업과 해시 검증
- 게임 프로세스 상태와 명명 파이프 client
- 번역 데이터 정적 검증
- 릴리스 패키지 생성과 검사

### `VVooOverthrown.Protocol`

- 길이 prefix JSON 메시지
- handshake에 프로토콜/트레이너/게임 빌드와 capability 포함
- `Query`, `Set`, `Toggle`, `ResetAll`, `Status` 동작
- 안정된 오류 코드: 지원하지 않는 빌드, 게임 상태 미준비, 멀티플레이 차단,
  capability 없음, 잘못된 값, Helper 내부 오류

### `VVooOverthrown.Helper`

- BepInEx 6 IL2CPP 플러그인
- 시작 시 빌드 지문을 재검증하며 실패 시 읽기·쓰기 명령을 모두 거부
- Unity 메인 스레드 dispatcher
- Mirror 연결을 검사하는 `OfflineSessionGuard`
- 한국어 글꼴과 번역표를 다루는 `KoreanLocalizationService`
- 각 기능이 독립적인 의존성을 선언하는 capability adapter
- 연결 종료, 멀티플레이 전환, Helper 종료 시 토글 효과 초기화

### `translation/`

- `source.en.json`: 원문 키와 영어 값
- `ko.json`: 검수된 한국어 값
- `glossary.ko.json`: 고정 용어
- `coverage.json`: 전체/번역/검수/누락 집계
- 추출·병합·토큰 검증 스크립트

## 5. 데이터 흐름

### 설치

1. App이 게임 루트와 지원 빌드 지문을 확인한다.
2. 실행 중이면 설치를 거부한다.
3. 사용자 데이터와 변경 대상 파일을 백업한다.
4. 새 고유 staging 폴더에서 payload 전체 해시를 검증한다.
5. BepInEx와 Helper, 번역 파일을 복사한다.
6. 설치된 각 파일의 상대 경로·해시·소유자를 manifest에 기록한다.
7. 실패하면 이번 작업에서 생성하거나 교체한 파일만 원복한다.

### 실행 및 연결

1. App이 게임을 실행하거나 기존 프로세스를 찾는다.
2. Helper가 지원 빌드와 번역 데이터를 검증한다.
3. Helper가 사용자별·프로세스별 명명 파이프를 연다.
4. App이 handshake와 capability를 받아 검증된 기능만 활성화한다.
5. 모든 Unity 접근은 Helper가 메인 스레드에서 수행한다.

### 한글화

1. 영어 문자열을 정규화하지 않은 원문 키로 우선 조회한다.
2. 서식 인수와 TMP rich-text 태그를 보존한 번역만 적용한다.
3. 한국어 glyph가 필요한 텍스트에 동적 한국어 fallback 글꼴을 연결한다.
4. 미번역 문자열은 영어로 남기고 로컬 누락 목록에 중복 없이 기록한다.

### 트레이너 변경

1. 각 명령 직전에 지원 빌드, 게임 준비 상태, capability를 확인한다.
2. `OfflineSessionGuard`가 원격 참가자 없는 로컬 세션인지 판정한다.
3. 원격 연결이 있거나 판정이 불확실하면 fail-closed로 거부한다.
4. 변경 전 원래 값을 런타임에 보관하고 `ResetAll` 또는 종료 때 복원한다.

## 6. 1차 capability

우선순위는 다음과 같지만 실제 interop 분석에서 안전하게 입증된 항목만 제공한다.

1. 플레이어 현재 체력/스태미나 조회
2. 체력/스태미나 고정 또는 소모 방지
3. 이동 속도 배율 조회·변경
4. 인벤토리 항목과 수량 조회, 선택 항목 수량 변경
5. 건설·제작·연구 시간 배율
6. 게임 시간 정지·배속

첫 실행 파일의 최소 런타임 합격 조건은 한글화 적용과 함께 1~3 중 적어도 하나가
실제 게임에서 성공하는 것이다. 나머지는 찾지 못한 의존성을 억지로 추측하지 않고
`지원 준비 중` capability로 남긴다.

## 7. 멀티플레이 차단

Overthrown은 싱글플레이에서도 로컬 host/client를 사용할 수 있으므로 단순히
`NetworkServer.active`만 검사하지 않는다. 로컬 연결 이외의 Mirror connection,
Steam lobby/원격 플레이어 흔적, 서버 권한 불일치 중 하나라도 확인되면 변경을
거부한다. 세션 도중 원격 참가자가 생기면 활성 토글을 즉시 초기화하고 App에
`MULTIPLAYER_BLOCKED` 상태를 보낸다. 판정 API가 확인되지 않으면 변경 기능은
기본적으로 비활성이다.

## 8. 오류 처리와 복구

- 지원하지 않는 빌드: 설치·연결·변경 차단, 현재/기대 해시 표시
- BepInEx 부팅 실패: 원본 게임 파일은 유지하고 진단 로그 제공
- 번역 파일 오류: 한글화만 비활성화하고 게임은 영어로 계속 실행
- Helper 예외: 해당 명령만 실패시키고 pipe loop와 게임 프레임을 유지
- 설치 실패: staging과 manifest를 기준으로 원복
- 제거: manifest 소유 파일 중 해시가 일치하는 파일만 삭제; 사용자가 변경한 파일은 보존
- 세이브 복원: 게임 실행 중 거부

## 9. 테스트 전략

### 자동 테스트

- 빌드 지문 일치/불일치
- 게임 경로 검증
- manifest 경로 탈출 방지, 설치 rollback, 보수적 제거
- 백업 생성과 해시 검증
- 프로토콜 framing과 메시지 검증
- 멀티플레이 guard의 로컬/원격/불확실 상태
- 기능별 Query/Set 의존성
- 번역 키 중복, placeholder, TMP 태그, 빈 문자열, coverage
- WPF ViewModel 상태 전이
- 패키지 필수 파일과 SHA-256

### 간단 통합 검증

- 릴리스 EXE가 실행되고 기본 화면이 뜨는지 확인
- 현재 게임 경로와 지원 빌드를 인식하는지 확인
- Helper 설치 후 게임을 한 번 실행해 BepInEx와 interop 생성 로그 확인
- Helper handshake와 한글화 초기화 확인
- 메인 메뉴의 대표 문자열이 한국어로 표시되는지 확인
- 싱글플레이에서 검증된 한 기능의 조회·변경·초기화 확인
- 테스트 후 에이전트가 시작한 게임과 앱을 정상 종료

## 10. 산출물

- `VVooOverthrown.exe` self-contained win-x64
- BepInEx/Helper/번역 payload
- `VVooOverthrown-win-x64.zip`
- ZIP과 내부 manifest SHA-256
- 한국어 사용자 가이드, 개발/분석 기록, 번역 기여 가이드

## 11. 완료 판정

- 모든 필수 자동 테스트와 Release 빌드가 성공한다.
- 실제 게임 빌드 지문 검증과 BepInEx 부팅 관문을 통과한다.
- 핵심 UI 한글화가 적용된다.
- 적어도 하나의 검증된 오프라인 트레이너 기능이 조회·변경·초기화된다.
- 멀티플레이 또는 불확실 상태에서 변경이 차단된다.
- 설치와 제거가 소유 파일 경계를 지킨다.
- EXE, payload, 문서, 체크섬이 릴리스 폴더에 존재한다.
